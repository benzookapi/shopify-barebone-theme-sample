レッスン 01 / 06

レイアウトから画面を読む

ホームと商品ページは同じレイアウトを使います。Shopify はヘッダーとフッターの間にある content_for_layout に、選択したテンプレートの内容を差し込みます。

!

よくある落とし穴

ホームだけの変更が商品ページにも出た

layout/theme.liquid に直接書いた内容は、同じレイアウトを使う全ページに表示されます。ホーム専用の表示は templates/index.json から呼ぶセクションに置きます。

試してみよう

サンプルのディレクトリで、自分のストアのドメインを指定して shopify theme dev --store your-store.myshopify.com を実行します。プレビューでホームから商品ページに移動し、共通する部分を探しましょう。

レッスン 02 / 06

JSON テンプレートで表示順を追う

templates/index.json の sections には、セクションのインスタンス ID とファイルを指定する type があります。各インスタンスの表示順は order で決まります。

!

よくある落とし穴

セクション名は合っているのに参照できない

このサンプルでは ID が my_home、型が home_page です。order には my_home を指定し、実装を読むときは型から sections/home_page.liquid を開きます。

試してみよう

順番を逆にすると何が先頭に来るか予想し、図のプレビューで確かめます。次にホームのテンプレートで2つの ID を探しましょう。

レッスン 03 / 06

セクションを追加できる場所を調べる

セクションは画面に出すマークアップとエディタ用のスキーマを持ちます。home_theme_blocks.liquid にはプリセットがあり、ホーム（index）に1つまで配置できます。

!

よくある落とし穴

ファイルがあるのに「セクションを追加」に出てこない

プリセット、編集中のテンプレートやセクショングループ、配置数の上限を確認します。このサンプルでは、テーマブロックの例はホームにすでに1つ配置されています。

試してみよう

テーマエディタでホームに配置済みのテーマブロックの例を開き、タイトルを変更します。セクション内の section.settings.title と表示を照合しましょう。

レッスン 04 / 06

ブロックとスニペットを使い分ける

マーチャントが何を編集するかを考えます。home_page.liquid には専用ブロック、home_theme_blocks.liquid には再利用できるリンクカードがあり、どちらも同じタイトル用スニペットを呼びます。

!

よくある落とし穴

blocks/ にカードを作ったのに表示されない

このリンクカードでは、親が @theme を許可し、content_for 'blocks' で子を描画します。カードのインスタンスも必要です。マーチャントはカードのプリセットから追加できます。

試してみよう

ホームで一方のリンクカードのラベルを変更し、もう一方のラベルが独立していることを確認します。index.json で link_card の2つのインスタンスを探しましょう。

レッスン 05 / 06

パンくずの階層をたどる

1つの商品は複数のコレクションに属せます。ヘッダーグループに「パンくず」を追加すると、商品ページではサンプルが次の順序で階層を探します。

!

よくある落とし穴

商品にカテゴリーがあってもパンくずが浅い

商品分類から階層を出すには、カテゴリー ID と一致するコレクションハンドルが1つ以上必要です。一致しなければ custom.breadcrumb_collections、次にメニューを確認します。どちらでも階層が見つからなければ「ホーム › ページタイトル」になります。

試してみよう

カテゴリーを設定した商品で、その ID とコレクションハンドルを比べます。パンくずのリンクがどのデータから作られたかを確認しましょう。ホームではパンくずは表示されません。

  • breadcrumbs.liquid ↗

レッスン 06 / 06

表示ルールが効く範囲を確かめる

オプションの顧客別コレクション・検索セクションは、顧客の custom.access_code と商品のリスト custom.access_codes を照合し、一致した商品のカードを表示します。

!

よくある落とし穴

カードを隠せば購入も制限できると思ってしまう

絞り込みが効くのはこの2つの一覧セクションです。商品ページの直接表示には別の制御が必要です。購入まで制限する場合は、サンプルの範囲外となるカート・チェックアウトでの検証も設計します。

試してみよう

開発テーマで標準のコレクション一覧を顧客別セクションに置き換えます。未ログイン時とコードが一致する顧客で一覧を比較し、その商品の詳細ページも確認しましょう。

トラブルシューティング

よくある
質問

GitHub Pages で実際のストアをプレビューできますか？

Pages ではこの教材と図解を閲覧できます。実際のストアデータで Liquid を描画するには、サンプルのディレクトリで shopify theme dev を実行し、CLI のプレビュー URL を開きます。後日も使う未公開テーマとして保存する場合は shopify theme push --unpublished を使います。

プレビューの手順 ↗
1つのテンプレートを編集すると、なぜ複数の商品が変わるのですか？

同じテンプレートを割り当てた商品は、セクションの構成を共有します。構成を変えるときは product.featured.json のような別テンプレートを作り、対象の商品に割り当てます。構成は同じで値だけ商品ごとに変えたいときは、対応する設定に動的ソースとして商品メタフィールドを接続できます。

動的ソースの仕様 ↗
スキーマの初期値を変えても、以前のタイトルが残るのはなぜですか？

既存のセクションには保存済みの値があります。たとえばホームのテンプレートには theme_block_examples のタイトルが設定済みです。テーマエディタでそのインスタンスを開き、保存されているタイトルを変更します。

ホームのテンプレート ↗
スニペットの中でローカル変数が空になるのはなぜですか？

render で呼んだスニペットは独自のローカルスコープを持ちます。必要な変数は名前付き引数で渡します。パンくずセクションでは menu_handle: section.settings.menu_handle として渡しています。

呼び出し元のコード ↗
@app を許可するとアプリブロックは自動で追加されますか？

スキーマの指定により、そのセクションがアプリブロックの配置先になります。対応ブロックを提供するアプリをインストールし、テーマエディタで追加します。ホームのテーマブロック用セクションでは content_for 'blocks' の位置に描画します。

アプリブロックの仕様 ↗
顧客別セクションを追加しても対象外の商品が表示されるのはなぜですか？

標準のコレクション・検索テンプレートには一覧セクションが配置済みです。標準の一覧と顧客別の一覧を両方置くと、それぞれが結果を表示します。この演習では、テーマエディタで対象テンプレートを確認し、標準の一覧を削除または非表示にします。

顧客別表示の設定手順 ↗
変更がテーマエディタに反映されないとき、最初に何を確認しますか？

CLI の出力で対象ストアとテーマを確認し、その開発テーマ用のエディタ URL を開きます。同期エラーやスキーマのエラーも確認します。同期後も古い内容が表示される場合は shopify theme dev を再起動し、表示された URL を開き直します。
